# PushyTao Blog Implementation Plan

**Goal:** Deliver a working, responsive technology blog and push it to the existing GitHub Pages repository.
**Architecture:** Hexo generates static HTML from Markdown and an original EJS theme. Client JavaScript progressively enhances navigation, search, filtering and reading utilities.
**Tech Stack:** Node 22+, Hexo, EJS, CSS, vanilla JavaScript.
**Spec:** ../specs/2026-10-01-blog-design.md

## Global constraints
- Preserve original content; original title-only C++ note is a draft.
- No invented personal details, analytics, credentials or copied reference-site assets.
- Brand PushyTao; deep blue and ice cyan default, accessible light mode.
- Source and deployment must remain usable with ordinary npm commands.

## Tasks
- [x] Foundation: package/config/scaffolds; two factual starter posts; draft migration; about/topics/404 pages; official Pages workflow and README.
- [x] Theme: EJS layout/partials/home/post/archive/category/tag/page; local SVG covers, responsive CSS.
- [x] Behavior: search index/feed/sitemap generators; browser search/filter/theme/menu/copy/progress; real generated-site checks and search matching tests.
- [x] Verification: clean install, generate and tests; visual and interaction review on desktop/mobile; independent code review.
- Delivery sequence: commit, synchronize original clean checkout via fast-forward, push main, inspect Pages run and live response. The Git history and Actions run provide the delivery record.

## Shared interfaces
Theme assets: /css/orbit.css, /js/orbit.js (type=module), /js/search.js, /images/orbit-hero.svg, /images/cover-orbit.svg, /images/cover-writing.svg, /images/favicon.svg.
Search JSON /search.json: array of {title,url,date,category,tags: string[],content}. Exclude drafts. Feed /atom.xml. Sitemap /sitemap.xml.
Client hooks: [data-search-open]; dialog#search-dialog with input#search-input, #search-results, #search-status, [data-search-close]. [data-theme-toggle]. [data-menu-toggle] and #site-nav. [data-filter] buttons ('all' or category text), [data-post-card][data-category], #filter-empty, #filter-count. #reading-progress, article .post-content pre, [data-back-top].
Client behavior uses hidden for filtered cards. Search rendering uses textContent, no untrusted HTML. Search module exports matchPosts(posts,query) for meaningful unit tests.
