这个站点有了一个新的起点。Orbit 用深蓝色的夜空、轨道线与明亮的留白，为文字留出足够的空间。这里会以文章为中心，逐步整理技术问题、实践过程，以及值得再次翻开的笔记。

<!-- more -->

## 一个可以慢慢积累的空间

一篇技术记录最有价值的部分，往往是当时遇到的具体问题：为什么选了某个方案，哪一步产生了误解，最后如何验证结果。把这些信息放回上下文里，比只留下结论更容易帮助未来的阅读者。

这个博客从两个入口开始：在首页阅读最近的文章，在[归档](/archives/)里按时间回看。也可以通过[专题](/topics/)寻找相近的主题，用搜索查找文章标题、标签或正文中的关键词。

## 让阅读保持简单

Orbit 的视觉从轨道与网格获得灵感，文章区域则保留了清晰的层次。桌面与手机使用同一份内容；浅色与深色外观可以切换，阅读时可以通过目录跳转到对应章节。

代码示例使用独立的代码块。下面是这个站点的基本生成命令，完整的写作步骤见[从 Markdown 到发布](/posts/writing-with-hexo/)。

```bash
npm ci
npm run build
npm run check
```

这些命令分别安装锁定的依赖、生成静态页面，以及检查生成结果。最终发布的是静态文件，读者不需要登录，也不需要运行一个后台服务。

## 保留过去，也给新内容留出位置

原仓库中保留着一份名为《视C++为语言联邦》的笔记。它在 2024 年 6 月 11 日加入仓库，但内容只有标题。原始文件仍然保留，并作为草稿迁入新的写作目录；补全内容后，才适合进入正式文章列表。

这次整理发布的两篇文章，分别介绍站点和写作流程。之后的内容可以从一个小而明确的问题开始：写下背景，记录实验，附上资料，再用自己的话说明结论。

## 从一篇记录开始

不必等到一个主题完全掌握才开始整理。一个可复现的小例子、一段对错误信息的解释，或者一次方案选择，都可以成为文章的起点。

让问题有来处，让结论有依据，让下一次回看时，仍然能够接上当时的思路。
